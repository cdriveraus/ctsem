# Stan-generated headers and stale objects

`configure` / `configure.win` run `rstantools::rstan_config()` on every
source install. That regenerates `src/stanExports_*.cc`/`.h` from
`inst/stan/*.stan` and rewrites `src/Makevars` / `src/Makevars.win` from
rstantools' own fixed template.

The staleness trap: `stanExports_X.cc` is a thin, model-name-only wrapper
around `stanExports_X.h` (an `Rcpp::exposeClass()` shim). Editing a `.stan`
file's data or parameters block regenerates `X.h` with new content and a new
mtime, but usually leaves `X.cc` byte-identical -- rstan_config()'s own
content-diffing (`rstantools:::.add_stanfile`) then leaves `X.cc`'s mtime
untouched. `make`'s only rule for the object is the built-in `%.o: %.cc`, so
it sees no change and relinks the stale `stanExports_X.o` against the old
header. The symptom is a data-dimension mismatch at fit time that reads
exactly like a code bug, not a build one -- there is no compile error,
because nothing recompiled.

Fixed by appending a prerequisite-only pattern rule,
`stanExports_%.o: stanExports_%.h`, to `src/Makevars`/`src/Makevars.win`
after every `rstan_config()` call. It cannot be added to the generated
Makevars files directly: `rstan_config()` always stamps them with the
"Generated by rstantools. Do not edit by hand." marker, and
`rstantools:::.setup_Makevars()`/`.add_stanfile()` unconditionally overwrite
any file carrying that marker on the next configure run, discarding anything
appended there by hand. `configure` and `configure.win` themselves are not
regenerated by an ordinary install (only by a maintainer explicitly re-running
rstantools' package-skeleton tooling), so appending the rule from inside them,
right after the `rstan_config()` line, survives every install. See the
comments in both files for the mechanics.

This changes nothing about what a maintainer does: `git clone` + ordinary
`R CMD INSTALL`/`devtools::install()` builds the stan backend exactly as
before. The only behavioural change is that an object whose generated header
changed now actually recompiles instead of being silently reused.

To prove it still works after touching this: delete `src/stanExports_*.o`,
touch (or edit) an `inst/stan/*.stan` file, reinstall, and confirm the
corresponding object's mtime moved. A full stan recompile from a clean `src/`
takes roughly 20 minutes; budget for it and do it once.
