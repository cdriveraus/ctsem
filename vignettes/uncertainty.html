A fitted ctsem model reports estimates and their uncertainty. How the uncertainty is computed depends on three settings:

  • optimize: sample the posterior (or likelihood) by MCMC, or find its mode and approximate the posterior around it.
  • priors: include ctsem’s weakly informative priors on the raw parameters, or leave them out.
  • uncertainty: for an optimized fit, which approximation to use around the mode.

This vignette fits one small model in each of these ways, with both backends (backend = 'stan' and backend = 'julia'), and compares the intervals.

Sampling and optimizing

Sampling (optimize = FALSE) draws from the posterior by MCMC, with Stan’s sampler for backend = 'stan' and the Julia engine’s own samplers for backend = 'julia'. The uncertainty is the spread of the draws, and no normal approximation is involved. This is the most reliable approach and the slowest.

Optimizing (optimize = TRUE, the default) finds the mode and approximates the uncertainty from the curvature there. This takes a single fit, but the approximation is a normal distribution, which describes a skewed, bounded or multimodal posterior poorly. Variance parameters estimated from few subjects often have such posteriors.

For a given priors setting both approaches target the same density. The sections below compare them, show the options between a single Hessian and full sampling, and then show what changes without priors.

A small model, fit several ways

The model is a single latent process measured by one indicator with a fixed intercept, and estimates a continuous time intercept, drift and diffusion. Eight subjects with eight time points each keep the fits fast, and the sample is small enough that the uncertainty methods give visibly different answers.

The two backends store the estimate and the draws in different places (fit$stanfit$rawest and fit$stanfit$rawposterior for stan, fit$estimate$raw and fit$estimate$rawposterior for julia). summary() and ctExtract() work with either and report parameters on their natural scale, so the comparisons below use ctExtract().

drift_interval <- function(fit) {
  draws <- ctExtract(fit)$pop_DRIFT[, 1, 1]
  c(mean = mean(draws), quantile(draws, c(.025, .975)))
}

By default an optimized fit draws its rawposterior from a normal approximation based on the Hessian (uncertainty = "hessian"). The next section shows the alternatives.

Alternatives to the Hessian

For an optimized fit, uncertainty in optimcontrol (when fitting) or method in ctFitUncertainty() (after fitting, from the same estimate) chooses how the uncertainty is computed. ctFitUncertainty() was called ctOptimUncertainty() in earlier versions, and the old name still works.

  • hessian: the curvature at the optimum, by finite differences on stan and exactly on julia, with draws from the matching normal distribution. This is the default and the cheapest. On julia the fit also checks the normal approximation, as checked does, and says if the posterior departs from it. It suits model building, and sampling is better for intervals you report.
  • checked: the hessian normal, checked against the gradient of the log posterior at 16 to 256 draws, and corrected by importance sampling in the directions where it is wrong, such as a skewed parameter or a variance that changes the width of other parameters. If the correction would cost more than the fit, for instance along a curved ridge, the hessian normal is kept and a warning names the parameters. When nothing is wrong the result is the hessian result. The corrected directions are sampled with the other parameters held near the estimate, so intervals can stay too narrow where a population standard deviation widens the effects it scales.
  • opg: the outer product of per-subject scores, with no Hessian. It is mainly a diagnostic.
  • sandwich: the robust covariance, with the Hessian as bread and the covariance of per-subject scores as meat. Useful as a check for misspecification.
  • bootstrap: a one-step bootstrap of the per-subject scores, using the Hessian. Much cheaper than refitting, but it needs enough subjects to be stable. With few subjects, expect a warning and a wider, noisier interval.
  • fullbootstrap: resample subjects and refit each sample. The most expensive method, and only available with backend = 'stan'.
  • is: importance sampling, with the Hessian’s normal as the proposal. It reweights the draws towards the objective the fit maximised. Here that is the exact posterior. With random effects it includes the approximation used to integrate them (see below).
methods <- c("hessian", "checked", "opg", "sandwich", "bootstrap", "is")

    updated <- ctFitUncertainty(base_fit, method = m, finishsamples = 200, cores = 1)
    data.frame(backend = backend_label, method = m, t(drift_interval(updated)))
  }))
}

Estimating the states

Everything above uses intoverstates = TRUE, the default. A Kalman filter integrates over the latent states, and the fit’s objective is the marginal likelihood (or posterior) of the parameters. With intoverstates = FALSE the states are estimated along with the parameters. This can help with non-Gaussian indicators, because backend = 'julia' then uses the exact observation density, where the filter uses an approximation.

Optimizing such a model would find the joint mode of parameters and states, which is not a useful estimate. With an innovation for every observation, the states can absorb almost any change in the parameters, and variance parameters are biased downwards, as they are when random effects are maximised as if they were parameters. ctFit() therefore refuses optimize = TRUE with intoverstates = FALSE, and optimcontrol$estonly = TRUE returns the mode anyway. For such a fit only uncertainty = 'hessian' is available, because the other methods use the marginal likelihood, which the fit did not maximise. The Hessian is taken with the states profiled out, and on a model this small it is nearly flat:

count_gen <- ctModel(

With random effects

The model so far has no individual differences. When parameters vary over subjects, the random effects can be integrated out or sampled, and this decides what an interval describes.

  • Integrated out: an optimized fit, with intoverpop = TRUE or the default 'auto'. Random effects that shift a mean in a model with Gaussian indicators are integrated exactly, and others with a Laplace approximation. Every uncertainty method above, is included, then describes this integrated objective and its approximation. Each fit checks the Laplace approximation and says if it affects the estimates, and intoverpop = 'quadrature' refines the fit. The interval is still a normal approximation at a mode, and a population standard deviation estimated from few subjects usually has a skewed posterior.
  • Sampled: optimize = FALSE, or ctFitUncertainty(fit, 'sample') after an optimized fit. The parameters and each subject’s random effects are drawn together from their joint posterior.

Sampling can be quick. It stops when targets for the effective sample size and R-hat are met, and lower targets give a rougher posterior with a known precision. A reported 5% or 95% quantile has a Monte Carlo error of about 1.96 * 2.1 / sqrt(ESS) posterior standard deviations, and the median 1.96 * 1.25 / sqrt(ESS). Chains whose means differ by d standard deviations show an R-hat of about sqrt(1 + d^2). minESS = 50 with rhatTarget = 1.07 aims at about half a posterior standard deviation at the centre. On the models we compared, four chains of 100 to 200 draws were already more accurate than the Laplace normal approximation, at two to three times the cost of the fit. For runs of less than about a minute, keep the chains in the R session (processes = FALSE), because starting Julia in a separate process for each chain takes tens of seconds.

Here a drift that varies over 30 subjects is summarised three ways. It is a random effect on the dynamics, so 'auto' integrates it with the Laplace approximation:

With and without priors

priors = TRUE adds ctsem’s priors on the raw parameters to the objective, and priors = FALSE, the default for ctFit(), leaves them out. ('randomCorr' puts a prior on random effect correlations only, so for a model with no random effects, like this one, it is the same as FALSE.) Together with optimize that gives four combinations:

priors = TRUE priors = FALSE
optimize = TRUE MAP: posterior mode, curvature around it MLE: likelihood maximum, curvature around it
optimize = FALSE posterior draws likelihood draws (see below)

The first three are shown above. stan_map and julia_map are MAP fits, an MLE fit is the same call with priors = FALSE, and stan_sample and julia_sample are posterior draws. The fourth, priors = FALSE with optimize = FALSE, is easy to ask for by accident, and both backends warn about it:

The posterior draws earlier stayed within a couple of units of zero on the raw scale. Without a prior, the raw parameters are limited only by what the likelihood identifies, and for a model and sample this small that is not much. At these settings the julia backend often warns that some sampled parameters “reached the region where their transform is flat to machine precision”, where the posterior is improper and the chains wander. Warnings are hidden in this rendering, but that one is worth reading in an interactive session. With stan the same problem shows as a slow warm-up, and the draws are not reliable either.

For a well identified model with enough data, sampling the likelihood with priors = FALSE is a reasonable choice. For a small or weakly identified model the raw parameters can wander, as they do here, so priors = TRUE is the safer choice for sampling, whatever the default for optimizing.

Summary

  • For a given priors setting, sampling and optimizing target the same density. Sampling returns draws, and optimizing returns a point estimate with an approximation around it.
  • For an optimized fit, uncertainty chooses the approximation. hessian is the cheapest and the default, and checked corrects it where it is wrong. opg, sandwich and bootstrap use per-subject scores and need enough subjects. fullbootstrap (stan only) refits resampled data and is the most expensive, and is uses the Hessian’s normal as an importance sampling proposal.
  • With random effects, the uncertainty of an optimized fit describes the integrated objective, including its approximation, whichever method is used. ctFitUncertainty(fit, 'sample') samples the joint posterior, and a lower minESS and higher rhatTarget make that quicker, with a known precision.
  • intoverstates = FALSE is for sampling, which draws the states along with the parameters. Optimizing is refused unless optimcontrol$estonly = TRUE asks for the joint mode, and then only hessian is available.
  • Priors change the objective: MAP or MLE when optimizing, the posterior or the likelihood when sampling. Sampling the likelihood of a small or weakly identified model needs care, because the chains can wander.
