library(ctsem)

ctModel() describes a model as a set of matrices. If you know lavaan, Mplus or brms, you can write the same model in a syntax close to the one you know:

Function Style Looks like
ctModel() matrices DRIFT = matrix(c('a11', 'a12', 0, 'a22'), 2, 2)
ctModelLavaan() lavaan eta1 ~ eta1 + eta2
ctModelMplus() Mplus eta1 ON eta1 eta2;
ctModelFormula() R formulas, as in brms d(eta1) ~ eta1 + eta2

All four return the same kind of model object. Fitting, summaries, plots and the functions that extend a model work the same way whichever you use, and ctModelSyntax() translates a model from one style to another.

One model, four ways

Two processes, each measured by one variable, with effects in both directions. With ctModel() this is the default model for a two by two loading matrix.

m_matrix <- ctModel(LAMBDA = diag(2), silent = TRUE,
  manifestNames = c('Y1', 'Y2'), latentNames = c('eta1', 'eta2'))

m_lavaan <- ctModelLavaan('
  eta1 =~ Y1                 # eta1 is measured by Y1
  eta2 =~ Y2
  eta1 ~ eta1 + eta2         # effects on eta1
  eta2 ~ eta1 + eta2         # effects on eta2
')

m_mplus <- ctModelMplus('
  eta1 BY Y1;
  eta2 BY Y2;
  eta1 ON eta1 eta2;
  eta2 ON eta1 eta2;
')

m_formula <- ctModelFormula(
  Y1 ~ eta1,                 # Y1 measures eta1
  Y2 ~ eta2,
  d(eta1) ~ eta1 + eta2,     # change in eta1
  d(eta2) ~ eta1 + eta2)

all.equal(m_matrix$pars, m_lavaan$pars)
#> [1] TRUE
all.equal(m_matrix$pars, m_mplus$pars)
#> [1] TRUE
all.equal(m_matrix$pars, m_formula$pars)
#> [1] TRUE

A regression between processes is an effect over time. In a continuous time model (type = 'ct', the default) eta1 ~ eta2 is the effect of the current level of eta2 on the rate of change of eta1, an entry of the drift matrix. With type = 'dt' it is the effect of eta2 at one occasion on eta1 at the next. The effect of a process on itself is its auto effect.

What is estimated when you say nothing

Loadings, effects between processes and effects of predictors are in the model only if you write them. Everything else follows the defaults of ctModel().

Part of the model Default
Loading of the first indicator of a process fixed to 1
Other loadings that are written free
Auto effect of each process free
Effects between processes zero unless written
Process noise (diffusion) variances and covariances free
Initial means, variances and covariances of the processes free
Intercepts of the indicators free, and different for each subject
Intercepts of the processes zero
Residual variances of the indicators free
Residual covariances of the indicators zero

Two of these differ from what lavaan or brms users may expect. The intercept of each indicator varies between subjects, because stable differences between people are usually present in repeated measures data. The noise of different processes is also correlated. Both can be switched off, as shown below.

Fitting

The model is fitted with ctFit() like any other. The data are in long format with one row per subject and occasion. Here a time dependent predictor TD1 affects the first process. The example data set is small, so the fit uses the default priors.

model <- ctModelLavaan('
  eta1 =~ Y1
  eta2 =~ Y2
  eta1 ~ eta1 + eta2 + TD1
  eta2 ~ eta1 + eta2
')
fit <- ctFit(ctstantestdat, model, priors = TRUE, cores = 2)
round(summary(fit)$popmeans, 2)

The rows are named by parameter. drift_eta1_eta2 is the effect of eta2 on eta1, and td_eta1_TD1 the effect of the predictor. These names are also how you refer to a parameter inside the syntax, which a later section uses.

Fixing, freeing and labelling

A number fixes a parameter, a name labels it, and two parameters with the same label are equal.

m <- ctModelLavaan('
  eta1 =~ NA*Y1 + Y2           # NA frees the first loading
  eta2 =~ Y3 + 0.8*Y4          # a loading fixed to 0.8
  eta1 ~ a*eta1 + eta2         # auto effect labelled a
  eta2 ~ a*eta2                # the same label: equal auto effects
  eta1 ~~ 0.25*eta1            # noise variance of eta1 fixed to 0.25
  eta1 ~~ 0*eta2               # uncorrelated noise
  Y1 ~~ Y2                     # a residual covariance
  Y3 ~ 0*1                     # intercept of Y3 fixed to zero
  eta2 ~ 1                     # free intercept for the process eta2
')

The same in Mplus style, where @ fixes, * frees and a name in parentheses labels the parameters before it on the same line:

m_mplus <- ctModelMplus('
  eta1 BY Y1* Y2;
  eta2 BY Y3 Y4@0.8;
  eta1 ON eta1 (a)
          eta2;
  eta2 ON eta2 (a);
  eta1@0.25;
  eta1 WITH eta2@0;
  Y1 WITH Y2;
  [Y3@0];
  [eta2];
')
all.equal(m$pars, m_mplus$pars)
#> [1] TRUE

In formula style the modifier stands before the term, and a label is quoted. An intercept is written as 1, removed with 0, or fixed with a number. A d() formula has no intercept unless 1 is written.

m_formula <- ctModelFormula(
  Y1 ~ NA*eta1,
  Y2 ~ eta1,
  Y3 ~ 0 + eta2,
  Y4 ~ 0.8*eta2,
  d(eta1) ~ "a"*eta1 + eta2,
  d(eta2) ~ 1 + "a"*eta2,
  diff_eta1 ~ 0.5,             # a parameter by name: the noise sd of eta1
  diff_eta2_eta1 ~ 0,          # no noise covariance
  mvarY2_Y1 ~ 1)               # estimate the residual covariance
all.equal(m$pars, m_formula$pars)
#> [1] TRUE

Formula style has no ~~, so variances and covariances are set through their parameter names, which are described below. In lavaan and Mplus style a value given with ~~, WITH or a variance statement is a variance or covariance, and only zero can be given for a covariance.

Differences between subjects

Any parameter can vary between subjects, and any parameter can depend on a subject level covariate (a time independent predictor). In lavaan and Mplus style, label the parameter and then write statements about the label.

m <- ctModelLavaan('
  eta1 =~ Y1
  eta2 =~ Y2
  eta1 ~ eta1 + cross*eta2
  eta2 ~ eta2
  cross ~~ cross               # the cross effect varies between subjects
  cross ~ TI1                  # and depends on the covariate TI1
')

Mplus users will recognise a random slope, followed by a between level model. Inside %BETWEEN% (or level: 2 in lavaan style) the name of an indicator stands for its intercept.

m_mplus <- ctModelMplus('
  eta1 BY Y1;
  eta2 BY Y2;
  cross | eta1 ON eta2;
  eta2 ON eta2;
  %BETWEEN%
  cross ON TI1;
')
all.equal(m$pars, m_mplus$pars)
#> [1] TRUE

# intercepts that depend on TI1, and no random intercept for Y2
m_between <- ctModelMplus('
  eta1 BY Y1;
  eta2 BY Y2;
  %BETWEEN%
  Y1 Y2 ON TI1;
  Y2@0;
')

In formula style, random effects are written as in lme4 and brms. A term such as (eta2 | id) lets the effect of eta2 vary over id. Predictors of a parameter go in a formula of their own, with the parameter on the left.

m_formula <- ctModelFormula(
  Y1 ~ eta1,
  Y2 ~ eta2,
  d(eta1) ~ eta1 + "cross"*eta2 + (eta2 | id),
  d(eta2) ~ eta2,
  cross ~ TI1)
all.equal(m$pars, m_formula$pars)
#> [1] TRUE

A formula for a parameter can say everything about it. 1 estimates it, a number fixes it, (1 | id) makes it vary, (0 | id) stops it varying, and s() gives a smooth effect of a covariate.

m <- ctModelFormula(
  Y1 ~ eta1,
  Y2 ~ eta2,
  d(eta1) ~ eta1 + eta2,
  d(eta2) ~ eta2,
  drift_eta1_eta2 ~ TI1 + (1 | id),   # varies, and depends on TI1
  mm_Y1 ~ s(TI2, k = 5),              # smooth effect on the intercept of Y1
  mm_Y2 ~ (0 | id))                   # no random intercept for Y2

All random effects in a model are correlated with each other. poprank and popblocks in ctFit() give their covariance a simpler structure.

Parameter names

Every parameter has a name. It is your label if you gave one, and otherwise the default name, which print(model) and summary(fit) show.

Parameter Default name
Auto effect of eta1 drift_eta1
Effect of eta2 on eta1 drift_eta1_eta2
Noise sd of eta1, noise covariance parameter diff_eta1, diff_eta2_eta1
Process intercept cint_eta1
Initial mean, sd, covariance parameter T0m_eta1, T0var_eta1, T0var_eta2_eta1
Loading of Y2 on eta1 lambda_Y2_eta1
Intercept of Y1 mm_Y1
Residual sd of Y1, residual covariance parameter mvarY1, mvarY2_Y1
Effect of the time dependent predictor x on eta1 td_eta1_x

In all three styles a statement with a parameter name on the left is about that parameter. This reaches the parts of a ctsem model that lavaan, Mplus and brms have no words for, such as the initial state.

m <- ctModelLavaan('
  eta1 =~ Y1
  T0m_eta1 ~ 0*1                 # initial mean fixed to zero
  drift_eta1 ~~ drift_eta1       # the auto effect varies between subjects
  diff_eta1 ~ TI1                # the noise depends on TI1
')

m_mplus <- ctModelMplus('
  eta1 BY Y1;
  [T0m_eta1@0];
  drift_eta1;
  diff_eta1 ON TI1;
')
all.equal(m$pars, m_mplus$pars)
#> [1] TRUE

A value given to a parameter by name is on the scale ctsem stores. For diff_eta1, T0var_eta1 and mvarY1 that is a standard deviation.

Indicators that are not Gaussian

The type of each indicator is an argument. Binary, ordinal, count and censored indicators are available.

m <- ctModelLavaan('
  ability =~ item1 + item2 + rating + errors',
  manifesttype = c(item1 = 'binary', item2 = 'binary', rating = 'ordinal',
    errors = 'count'),
  ncategories = c(rating = 5))
m$manifesttype
#> [1] 1 1 2 3

Thresholds written in the native way also declare a binary or ordinal indicator: rating | t1 + t2 + t3 + t4 in lavaan style, and [rating$1 rating$2 rating$3 rating$4]; in Mplus style. ctModelFormula() also takes family, as in family = list(item1 = 'bernoulli', errors = 'poisson'). See the vignette on measurement models for what each type assumes.

More than one level

If subjects are nested in groups, give both id columns, innermost first, and name the level a parameter varies at.

m <- ctModelLavaan(id = c('person', 'school'), '
  eta1 =~ Y1
  level: person
  drift_eta1 ~~ drift_eta1       # auto effect varies between persons
  level: school
  Y1 ~~ Y1                       # intercept varies between schools only
')

m_formula <- ctModelFormula(id = c('person', 'school'),
  Y1 ~ eta1 + (1 | school),
  d(eta1) ~ eta1 + (eta1 | person))
all.equal(m$pars, m_formula$pars)
#> [1] TRUE

In Mplus style the blocks are %BETWEEN person% and %BETWEEN school%.

Other ctsem features

A cell of a ctsem model can also carry a transform, a prior scale for its random effect, a stated population mean, or an expression of the latent states. Wherever a label can be written, a ctPar() call or a quoted ctsem cell can be written instead.

m <- ctModelLavaan(PARS = 'damp', '
  eta1 =~ Y1
  eta2 =~ Y2
  # a positive cross effect, with a tighter prior on how much it varies
  eta1 ~ eta1 + ctPar(cross, transform = "exp(param)", indvarying = TRUE, sdscale = 0.5)*eta2
  # an auto effect that depends on the level of the process
  eta2 ~ "-exp(damp) * (1 + eta2^2)"*eta2
')

In Mplus style the same goes in the parentheses that hold a label, as in eta1 ON eta2 (cross|exp(param)|TRUE|0.5);. The arguments of ctModel() that are not matrices can be passed to all three functions, for example driftScaled, PARS and tipredDefault.

The result is an ordinary model, so everything that works on a model from ctModel() works here.

m <- ctModelFormula(Y1 ~ eta1, Y2 ~ eta2,
  d(eta1) ~ eta1 + eta2, d(eta2) ~ eta2)
m2 <- ctModelHigherOrder(m, indices = 1)   # second order dynamics for eta1
m$pars$indvarying[m$pars$param %in% 'drift_eta2'] <- TRUE   # edit a cell directly

A model saved with saveRDS() can also be opened in the ctsem GUI (the ctsemGUI package), which shows it as a diagram and as matrices.

Translating a model

ctModelSyntax() writes any model in any of the three styles, as code that creates it. Use it to see how a model you already have looks in another style, or to learn the names of its parameters.

m <- ctModelLavaan('
  eta1 =~ Y1 + Y2
  eta2 =~ Y3
  eta1 ~ eta1 + cross*eta2 + TD1
  eta2 ~ eta2
  eta1 ~~ 0*eta2
  cross ~ TI1
  cross ~~ cross
  level: 2
  Y3 ~~ 0*Y3
')
ctModelSyntax(m, 'mplus')
#> ctModelMplus(type = "ct", id = "id", time = "time", TIpredNames = c("TI1"), syntax = '
#>   eta1 BY Y1 Y2;
#>   eta2 BY Y3;
#>   eta1 ON eta1
#>           eta2 (cross)
#>           TD1;
#>   eta2 ON eta2;
#>   eta2 WITH eta1@0;
#>   cross ON TI1;
#>   cross;
#>   mm_Y3@0;
#> ')
ctModelSyntax(m, 'formula')
#> ctModelFormula(
#>   Y1 ~ eta1,
#>   Y2 ~ eta1,
#>   Y3 ~ eta2,
#>   d(eta1) ~ eta1 + "cross"*eta2 + TD1,
#>   d(eta2) ~ eta2,
#>   diff_eta2_eta1 ~ 0,
#>   cross ~ TI1 + (1 | id),
#>   mm_Y3 ~ (0 | id),
#>   type = "ct", id = "id", time = "time", TIpredNames = c("TI1"))

It also works on a model built with ctModel():

ctModelSyntax(m_matrix, 'lavaan')
#> ctModelLavaan(type = "ct", id = "id", time = "time", syntax = '
#>   eta1 =~ Y1
#>   eta2 =~ Y2
#>   eta1 ~ eta1 + eta2
#>   eta2 ~ eta1 + eta2
#> ')

What is done elsewhere

Some things that are part of the model syntax in lavaan, Mplus or brms are set in another place in ctsem.

You may be looking for In ctsem
Start values (start(), *0.5) ctFit(inits = )
Priors (prior(), MODEL PRIORS) ctFit(priors = TRUE), and sdscale in ctPar()
Bounds on a parameter (a > 0) a transform, ctPar("a", transform = "exp(param)")
Defined parameters (:=, MODEL CONSTRAINT) computed from the fit, for example with ctSummaryMatrices()
Multiple groups (group:, GROUPING) a time independent predictor of the parameters that may differ
A factor model for the random effects poprank and popblocks in ctFit()
Uncorrelated random effects (||) not available, random effects are correlated
Lags beyond one (y&2), cycles, trends ctModelHigherOrder(), ctModelPeriodicComponent(), ctModelSlowComponent()
Stationarity ctFit(stationary = TRUE)
Interactions of processes (XWITH) a state dependent cell, see ?ctModel
Estimator and sampling settings (ANALYSIS:) arguments of ctFit()

If the syntax contains one of these, the functions stop and say where it is set. An Mplus input file can be pasted whole, and only its MODEL: section is read.
