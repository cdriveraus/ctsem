A fitted model can be wrong in ways its estimates do not show. Subjects may differ in a parameter the model holds fixed, a parameter may depend on a covariate that is not in the model, or the dynamics may depend on the level of the process. ctScoreTest() tests a fitted model, without refitting it, for whether such extensions would fit better:

  • heterogeneity: does a parameter differ between subjects, so that it should be individually varying?
  • covariates: does a parameter depend on a subject level covariate that is not in the model? This includes the size of a random effect as well as its mean.
  • state dependence: does a drift coefficient change with the level of a latent state, so that the dynamics are nonlinear?
  • volatility: does the size of a process’s random shocks change with the level of a state, for example negative affect being more variable when it is high?

Each is a score (Lagrange multiplier) test, based on the slope of the log likelihood at the fitted model in the direction of the extension. It needs a few evaluations of the fitted model’s gradient and no new fit for each candidate, so many candidates can be screened after one fit. Each test also gives a rough estimate of the size of the effect. The tests are screens that point to what to add, and refitting shows how much it matters.

The three examples below each generate data with something the fitted model lacks, fit the model without it, run ctScoreTest(), and refit with what it found. Later sections cover a fourth family of tests (cells the model fixes at zero), posterior predictive checks as tests (ctFitAdequacy()), and a search that combines both and does the refitting (ctModelImprove()).

The process

Two latent processes, each measured by one indicator, observed 30 times at irregular intervals for 150 subjects. eta1 returns towards its baseline at rate 0.6 and eta2 at 0.4, and eta1 pushes eta2 up, with a cross effect of 0.25. Each subject has their own measurement intercepts. The generating model is written once, and each example changes one cell of it.

generator <- function(DRIFT, MANIFESTMEANS = c("mm1|param|TRUE|1", "mm2|param|TRUE|1"),
  TIpredNames = NULL) {
  ctModel(type = "ct", silent = TRUE,
    manifestNames = c("Y1", "Y2"), latentNames = c("eta1", "eta2"),
    LAMBDA = diag(2), DRIFT = DRIFT, CINT = matrix(0, 2, 1),
    DIFFUSION = matrix(c(0.8, 0, 0, 0.6), 2, 2), MANIFESTVAR = diag(0.5, 2),
    MANIFESTMEANS = matrix(MANIFESTMEANS, 2, 1),
    T0MEANS = matrix(0, 2, 1), T0VAR = diag(1, 2), TIpredNames = TIpredNames)
}

The model fitted in every example is ctsem’s default for two latents with one indicator each. Every drift, diffusion and measurement error parameter is free and shared by all subjects, and the measurement intercepts and initial states vary over subjects.

model <- ctModel(type = "ct", silent = TRUE,
  manifestNames = c("Y1", "Y2"), latentNames = c("eta1", "eta2"),

1. Subjects who differ in a parameter

Here the subjects differ in how quickly eta1 returns to baseline. The drift DRIFT[1,1] varies between subjects around -0.6, with a standard deviation of about 0.25.

Each row tests whether that parameter varies over subjects, in the way ctFit() would fit it if it were made individually varying. That means its variance together with its covariances with the effects already in the model, here each subject’s initial state and measurement intercepts (named in the line under the table). A variance cannot be negative, so that part of the test is one sided, and LM is compared with an equal mixture of chi-square distributions on df - 1 and df degrees of freedom. The covariances matter most for an intercept. An intercept that varies independently of where each subject starts makes subjects drift apart from a common start, while the same intercept correlated with the initial state is a random intercept. z tests the variance alone, and p is the smaller of the two tests’ p-values.

The drift of eta1 is flagged on its variance alone (z). Other rows are flagged too, mostly through their covariances (LM large where z is small): the cross effect of eta2 on eta1, and the diffusion of eta2. This is expected. When a drift varies between subjects but is fixed in the model, how each subject’s data relate to their starting point and intercepts changes, and the scores of other parameters pick up some of that. The test shows that the subjects differ and roughly where, but cannot always say which of several related parameters is the source. To find out, free the strongest candidate and test again.

The line under the table tests all directions at once, for subjects varying along some combination of these parameters, with the covariances with existing effects held at zero. This can find variation spread over several parameters, which no single row isolates. Here one parameter carries the variation, and its own row is the sharper test. When the population covariance has reduced rank (poprank), the rows test variation outside the shared dimensions and the line is not given, because in simulations the rows found a missing dimension far more often.

2. A covariate the model does not contain

Now each subject has a standardised age, which matters in two ways. Older subjects have a higher intercept on Y1, and in older subjects eta1 pushes eta2 harder (the cross effect DRIFT[2,1] rises by 0.3 per standard deviation of age). A second covariate, w, is unrelated to anything.

For each covariate, the joint test asks whether it matters for any parameter. Each parameter’s row then gives the effect a refit with that covariate would be expected to estimate, per unit of the covariate. age is found, on the intercept of Y1 and on the cross effect, at about the sizes it was generated with, and w is not. The effects are estimated jointly, so a covariate that moves one parameter is not attributed to another parameter correlated with it. They are also estimated with the other parameters held at their fitted values. The model without age has already absorbed some of its effect, as the intercepts’ standard deviation has grown to take in the age differences, and letting those parameters move as well would extrapolate the model’s curvature over that whole change.

The tests also cover the standard deviations of the random effects (the popsd_ rows), that is, whether subjects differ more at some ages than others. A covariate can also be tested as a step at an unknown threshold with form = "threshold", for an effect that switches on above some age, for example. This scans the possible cuts and allows for having chosen the best one.

The refit includes age as a time independent predictor, with effects on every parameter:

3. Dynamics that depend on the state

In the last example eta2 moderates how eta1 returns to baseline. When eta2 is high, eta1 returns more slowly. The drift of eta1 is -0.6 + 0.3 * tanh(eta2), so it ranges between -0.9 and -0.3, and near eta2 = 0 it rises by about 0.3 per unit of eta2.

gen3 <- generator(DRIFT = matrix(c("-0.6 + 0.3 * tanh(eta2)", 0.25, 0, -0.4), 2, 2))
d3 <- data.frame(ctGenerate(gen3, n = 150, Tpoints = 30, dtmean = 1,
  logdtsd = 0.5, backend = "julia", values = c(mm1 = 0, mm2 = 0)))

The fitted model is linear, with each drift coefficient a constant.

Each term is one drift coefficient changing linearly with one state. The term eta1*eta2 in the equation for eta1 stands out. Either the drift of eta1 changes with eta2, which is how the data were generated, or the effect of eta2 on eta1 changes with eta1. To first order these are the same term, so the table names both, and which to fit is a substantive choice. The estimate is the change in the drift coefficient per unit of the state. The term now in the model has no score left, and no other term stands out.

The test evaluates each candidate term at the state predicted from earlier observations. Because that prediction has not seen the observation being scored, the observation’s contribution to the score has mean zero when the model is right. Smoothed or updated state estimates do not have this property, and in simulations, tests using them as covariates rejected correct models nearly every time.

The polynomial terms assume the dependence is smooth enough to show in a linear term. tests = "instability" makes no assumption about its form. It takes each observation’s score, which says how much that observation pulls on each parameter, and orders the observations by time and by each latent’s state as predicted from earlier observations. Under the model, the running sum of the scores behaves like a Brownian bridge in any order. A parameter that changes over the study, or differs between low and high levels of a state, bends it.

The state dependence stands out, in the drift of eta1 and in the size of its innovations. So does the measurement error covariance between Y1 and Y2, although the data were generated without one, probably as another effect of the missing moderation. The heterogeneity tests stay quiet here, but need not. A drift that changes with the state can also look like a drift that differs between subjects, and in simulations a missing nonlinearity did affect them. A badly misspecified model can show up in several tests at once, so free what stands out most, refit, and test again.

Do the model’s predictions look like the data?

The usual check of a dynamic model compares the data with data generated from the fitted model: the autocorrelations and cross-correlations (ACF and CCF), how much subjects differ from each other, and so on. ctFitAdequacy() turns these comparisons into tests, grouped in families aimed at different kinds of misfit.

Most families use the one-step-ahead prediction errors. Under the model these are independent and standard normal however the observations are spaced, so no generated data are needed. Each variable’s error is taken given the other variables observed at the same time, so a result points to a variable.

  • residuals: correlations of the errors within subjects, over every pair of a subject’s observations, binned by the time between them. This is the residual ACF and CCF in continuous time. A slow process missing from the model shows as correlation over the time gaps it spans.
  • latent: the same for each latent process, using the standardised change in the predicted state at each observation, correlated with the same subject’s changes at other times. With many indicators per process, each item’s errors can be nearly uncorrelated while the processes themselves are misspecified, for example with a cross effect missing. One statistic per process detects this more easily than one per item.
  • volatility: the same for the squared errors, for variance that clusters in time.
  • pairs: whether two variables’ errors at the same time correlate as the model says, for a wrong measurement error covariance or loading.
  • periodic: a cycle the model lacks, such as a daily rhythm, from the periodogram of each variable’s errors and each process’s updates. It depends only on the time between observations, so it finds a rhythm whatever its phase in each subject. Give the periods that matter (periods = 24 with time in hours), or by default it scans a range.
  • tvcovariates (when tvcovariates are given): whether time varying variables the model does not use predict its errors, at the same and the previous observation.
  • distribution: skewness, kurtosis and outlying occasions.
  • fit: whether some subjects fit much worse than the model allows.
  • dependence: whether an error or its size depends in any way on what came before: the predicted states, the previous errors, or the time since the last observation.
  • effects: for random effects integrated with intoverpop = "laplace", whether their normal distribution fits. At cuts along each axis, each subject’s posterior probability that its effect lies below the cut is averaged over subjects. Under the model this average matches the normal distribution, and a skewed or bimodal distribution of subjects moves it.
  • scores (when asked for): whether each observation’s score is uncorrelated with the scores of the same subject’s other observations, which holds under the model. This checks for any kind of dynamic misspecification, but is weak because it is spread over many statistics. The targeted tests above detect what they cover far more often.

The error statistics allow for the parameters having been estimated from the same data, by projecting each subject’s contribution on its scores, as the score tests do. Three further families compare statistics of the data with generated data: the spread over subjects of their own means, standard deviations and lag one correlations, whether change depends nonlinearly on level, and, when covariates are given, whether the subjects’ statistics depend on them. With many observations every misfit becomes significant, so the size of the remaining misfit is also reported, as the root mean square residual correlation of the items and of the latent processes, with intervals and a test of whether each is at most close (0.05 by default).

Only the pairs family fails, on the same measurement error covariance the score tests flagged, and the remaining correlations are within the close-fit bound. The state dependence that the score test found (adjusted p of 2e-6) does not show. A moderated drift, averaged over the data, still decays much like a single exponential, so the errors it leaves are nearly uncorrelated and the root mean square residual correlation is close to zero. The checks are useful for things no score test covers: a missing slow process, variance that clusters, errors with heavy tails, or a process of the wrong order. In simulations the residual correlations over time gaps found a missing slow process (with a time constant ten times the fast one’s) in 65 of 100 data sets, where correlations at a few lags found it in 5. Passing the checks does not show that the model is right, which is why the search in the next section screens with the score tests and stops on the checks.

Automating the search

ctModelImprove() runs the tests in a loop. It screens the fit, refits with the most strongly indicated changes one at a time (starting from the current estimates), and keeps the best if the refit’s likelihood confirms it. It repeats this until nothing more is indicated, and then checks the model with ctFitAdequacy(). If a check fails, it tries structural changes the score tests cannot propose: a slow process driving a latent (ctModelSlowComponent()), tried first for a latent whose updates stay correlated over long gaps; a daily or other cycle at the period the periodic family points to (ctModelPeriodicComponent()); a separate process for an item whose errors stay correlated over time (ctModelUniqueProcess()); a second order process (ctModelHigherOrder()); or models you supply. Finally it tries removing each change it kept, in case a later change made it unnecessary.

Here the data have two of the problems above. age affects the intercept of Y1 and the cross effect, eta2 moderates how eta1 returns to baseline, and w is unrelated.

Each round shows what was tried, the score test that proposed it, and the result of the refit. The first round added age as a predictor of the intercept of Y1, and the second the moderation. The model was chosen using the data it is fitted to, so its standard errors and tests are too optimistic about the structure the search added. Treat that structure as a hypothesis to confirm on other data. Within one data set, holdout = 0.3 sets aside 30 per cent of the subjects. The search runs on the rest, and each change it keeps is then tested on the held-out subjects alone. With a large data set, close = 0.05 also stops the search once the remaining residual correlations are not significantly larger than 0.05, since otherwise every small misfit would be significant.

How the tests work, briefly

  • The scores are those of the objective the model was fitted with, so they integrate over random effects in the same way as the fit. A covariate’s effect adds to a parameter’s raw value, so its score is the covariate times each subject’s score for that parameter. Any number of covariates therefore costs a few matrix products after one set of per-subject scores and Hessians.
  • At zero, a random effect’s variance has the score 12∑i(sij2+Hi,jj)\frac{1}{2}\sum_i (s_{ij}^2 + H_{i,jj}), and its covariance with an existing effect has the score ∑i(sijsir+Hi,jr)\sum_i (s_{ij} s_{ir} + H_{i,jr}). This is the information matrix test in those parameters, which is the score test for neglected heterogeneity. Every subject already has one such effect, their initial state, so the covariances are tested even in a model with no random effects.
  • State dependence is tested on the fitted model extended with the drift terms at zero, which gives exactly the same fit.
  • The fitted model’s curvature is used to project the fitted parameters out of each test and to size the one-step estimates. Each test’s variance comes from the spread of the subjects’ contributions, and its p-value from resampling subjects. This keeps a test valid when the model is wrong in some other way, which is when a screen is used. A variance based on the model’s curvature would make unrelated tests reject too.

The tests need subjects to be independent units, so a model with levels above the subject can only be tested for state dependence. See ?ctScoreTest for details.
