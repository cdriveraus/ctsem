# Decompose model implied variance into between person, process and measurement

Splits the variance each indicator of a fitted model implies into a
between person part, a within person part from the latent process, and a
within person part from measurement error. The process part is further
split into the contribution of the system noise and that of the mean
path changing over time.

## Usage

``` r
ctVarianceDecomposition(
  fit,
  method = c("auto", "moment", "simulation"),
  persons = c("auto", "model", "estimated"),
  scale = c("latent", "response"),
  times = NULL,
  npersons = 200L,
  npaths = 20L,
  latents = TRUE,
  quadpoints = 21L,
  subjects = "all",
  realid = TRUE,
  sources = NULL
)
```

## Arguments

- fit:

  fit object as generated by
  [`ctFit`](https://cdriveraus.github.io/ctsem/reference/ctFit.md), from
  either backend.

- method:

  How the model implied moments are computed. `'moment'` uses the
  forward moment recursion, which is exact and needs linear dynamics.
  `'simulation'` draws trajectories with the julia engine, for models
  with state dependent `DRIFT` or `DIFFUSION` cells. `'auto'`, the
  default, uses `'moment'` unless the model has such cells.

- persons:

  Which persons the between person variance refers to. `'model'` draws
  persons from the fitted population distribution of the random effects.
  `'estimated'` uses the subjects in the data. On a `backend='julia'`
  fit each subject is represented by its estimated effects plus a draw
  from their posterior. On a stan fit each subject is represented by its
  estimated (empirical Bayes) matrices, which understates the between
  person variance. `'auto'`, the default, uses `'model'` for julia fits
  and `'estimated'` for stan fits, and says which it used.

- scale:

  For a binary or ordinal indicator, whether to decompose the linear
  predictor behind the logit (`'latent'`, the default, with a
  measurement variance of \\\pi^2/3\\) or the observed response
  (`'response'`, integrating the link over each row's normal
  distribution). The two are the same for a Gaussian indicator.

- times:

  If given, decompose at each of these times. By default the
  decomposition averages over each person's observation times. Either a
  numeric vector, or `'asdata'` for the observed occasions. Every person
  is evaluated at the same times. The result gains a `time` column and
  has no `within.deterministic` column, since that term is the variance
  of the mean path over time. Not available with `method='simulation'`
  or with time dependent predictors.

- npersons:

  Number of persons to draw when `persons='model'`. With
  `persons='estimated'` on a julia fit, each subject gets enough draws
  to make at least this many persons in total.

- npaths:

  Trajectories drawn per person when `method='simulation'`. The result
  is unbiased for any `npaths`, but small values give noisy results.

- latents:

  If TRUE, also decompose the latent processes, which have no
  measurement component.

- quadpoints:

  Gauss-Hermite nodes used when `scale='response'`.

- subjects:

  `'all'`, or the subjects whose designs the decomposition is computed
  over, as ids in the data (see `realid`).

- realid:

  If TRUE (the default), subjects are read as the ids in the data, and
  integers that are not ids there are read as ctsem's numbering of the
  subjects, 1 to N, with a message. If FALSE, they are read as that
  numbering.

- sources:

  Optional named list of latent names, one entry per group of processes
  whose innovations are independent of the other groups, such as fast
  affect, a daily process and a slow process. The stochastic within
  person term is then split by source, into `within.stochastic.<group>`
  for each group's innovations and `within.stochastic.initial` for what
  remains of the initial state variance. These add up to
  `within.stochastic`. When averaging over the observation times,
  `level.<group>` gives the part of each group's term that is variance
  in a person's average level over their record. This shows how much a
  slow process acts as a stable level within the record. Needs
  `method='moment'`.

## Value

A data frame of class `ctVarianceDecomposition`, one row per variable,
with columns `variable`, `type`, `between`, `within.deterministic`,
`within.stochastic`, `within.measurement`, `within`, `total` and the
corresponding proportions. The population the between column refers to,
the scale, and the number of persons are recorded as attributes and
shown by `print`.

## Details

The decomposition applies the law of total variance over the (person,
occasion) pairs in the design of the fit. With \\g = E\[y \| \eta\]\\
the expected observation given the latent state,

\$\$Var(y) = E\[Var(y\|\eta)\] + E_i E_t Var(g) + E_i Var_t(E\[g\]) +
Var_i(E\[g\])\$\$

and the four terms are the four columns reported. They are non-negative
and sum to the total.

`within.deterministic` is the variance of a person's mean path over
their observation times. It is zero for a stationary process without
time dependent predictors, and positive when there is a trend, a shift
due to a predictor, or a process that has not settled from its initial
distribution.

The moments are computed over each subject's observation times without
using the observed values, so unequal spacing, missing observations and
time dependent predictors are all accounted for. The result is exact for
models with linear dynamics. For a model whose `DRIFT` or `DIFFUSION`
depends on the state, `method='moment'` is refused, and
`method='simulation'` applies the same decomposition to simulated
trajectories. State dependent measurement cells (`LAMBDA`,
`MANIFESTMEANS`, `MANIFESTVAR`) are not supported by either method.

**Random effect levels.** A model with a grouping level above the
subject (`id = c('subject','study')` in
[`ctModel`](https://cdriveraus.github.io/ctsem/reference/ctModel.md)),
fitted with `intoverpop='laplace'` or sampled, gets one
`between.<level>` column per level. Each is the variance of that level's
departure from the level above it, and together they sum to `between`.
Estimated random effects are shrunk towards the level above, more
strongly where a unit has little data, so `persons='estimated'` adds to
each estimate a draw from that unit's posterior.

**When the split changes over time.** The columns are averages over each
person's occasions. For a process that has not settled the split differs
between occasions, and `within.deterministic` is then large. Use `times`
to see the split at each time.

**Designs.** Each person is evaluated at their own observation times, so
balanced and unbalanced designs and missing observations are all
handled, and the result does not depend on which observations are
missing. Persons are weighted equally, however many observations each
has.

With `method='simulation'`, the function checks that the engine draws
the individually varying parameters, and stops with an error if it does
not.
