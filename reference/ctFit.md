# Fit a ctsem model

Fits a ctsem model specified via
[`ctModel`](https://cdriveraus.github.io/ctsem/reference/ctModel.md)
with type either 'ct' or 'dt'. `ctStanFit` is maintained as a
backward-compatible alias.

## Usage

``` r
ctFit(
  datalong,
  model,
  stanmodeltext = NA,
  iter = 1000,
  intoverstates = TRUE,
  binomial = FALSE,
  fit = TRUE,
  intoverpop = "auto",
  poprank = "auto",
  sameInitialTimes = FALSE,
  stationary = FALSE,
  plot = FALSE,
  derrind = NA,
  optimize = TRUE,
  optimcontrol = list(),
  backend = c("julia", "stan"),
  nlcontrol = list(),
  nopriors = NA,
  priors = FALSE,
  chains = 2,
  cores = getOption("mc.cores", 2L),
  inits = NULL,
  compileArgs = list(),
  forcerecompile = FALSE,
  saveCompile = TRUE,
  savescores = FALSE,
  savesubjectmatrices = FALSE,
  saveComplexPars = FALSE,
  gendata = FALSE,
  sampleControl = list(),
  control = list(),
  verbose = 0,
  ...,
  popunique = NULL,
  popblocks = NULL,
  weights = NULL,
  ctstanmodel
)
```

## Arguments

- datalong:

  long format data containing columns for subject id, time, manifest
  variables, any time dependent (i.e. varying within subject)
  predictors, and any time independent (not varying within subject)
  predictors.

- model:

  model object as generated by
  [`ctModel`](https://cdriveraus.github.io/ctsem/reference/ctModel.md)
  with type='ct' or 'dt', for continuous or discrete time models
  respectively.

- stanmodeltext:

  already specified Stan model character string, generally leave NA
  unless modifying Stan model directly. (Possible after modification of
  output from fitting with argument fit=FALSE.) `backend='stan'` only.

- iter:

  **Deprecated**, use `sampleControl$iter`. Still honoured, with a
  warning.

- intoverstates:

  Logical. TRUE (the default) integrates over the latent states with a
  Kalman filter. FALSE estimates the states along with the parameters,
  and the fit reports their trajectory in `fit$estimate$states`. FALSE
  is for sampling (`optimize=FALSE`). With `backend='julia'` it avoids
  the Gaussian approximation the filter makes for binary, ordinal and
  count indicators. `optimize=TRUE` is refused, because the joint mode
  of states and parameters is not a useful estimate. With
  `optimcontrol$estonly=TRUE` the mode is returned anyway, without
  standard errors.

- binomial:

  Deprecated. Logical indicating the use of binary rather than Gaussian
  data, as with IRT analyses. This now sets the `manifesttype` of every
  indicator to 1, for binary.

- fit:

  If FALSE, the model and data are prepared but not fitted. With
  `backend='stan'` the unfitted fit object is returned, and with
  `backend='julia'` the specification passed to the engine.

- intoverpop:

  How random effects (individual differences) are handled: integrated
  out of the likelihood, or sampled with the other parameters.

  `'auto'`, the default, integrates them out when optimizing, as `TRUE`
  does, and samples them (`'none'`) when `optimize=FALSE`. The exception
  is a julia fit in which every subject's likelihood is Gaussian in its
  random effects (a linear model with Gaussian indicators, and random
  effects only on means, with linear transforms). There the random
  effects are integrated exactly and the population parameters sampled
  (`'laplace'`).

  `TRUE` integrates them out, by `'laplace'` on `backend='julia'` and by
  `'augmented'` on `backend='stan'` or with `intoverstates=FALSE`.
  `fit$args$resolved$intoverpopreason` records which was used and why.

  `'laplace'` (`backend='julia'`) integrates random effects on a
  manifest mean, initial mean or continuous intercept of a linear
  Gaussian model exactly, and all other random effects by a Laplace
  approximation. With binary, ordinal or other non-Gaussian indicators,
  random effects on initial means are integrated by the Kalman filter
  together with the states.

  `'augmented'` adds each random effect to the states of the Kalman
  filter. This is exact for random effects on means in a linear Gaussian
  model, and a linear approximation elsewhere, which shrinks random
  effects on the dynamics. In a model whose dynamics depend on the
  state, a random effect on the dynamics or the initial mean can also
  overstate the likelihood and move the estimates, and variation in
  DIFFUSION or MANIFESTVAR parameters is only partly identified. ctFit
  warns in both cases.

  `'quadrature'` (`backend='julia'`, optimizing) fits by `'laplace'`,
  then refines the fit by integrating numerically the random effects of
  the subjects (or groups) that the random-effects check flags
  (`optimcontrol$checks`). The reported estimates, standard errors and
  log likelihood are from the refined fit, with the Laplace log
  likelihood kept in `loglik_laplace`. The refinement takes seconds to
  minutes, longer with nested levels. How far the integration's error
  may move the estimates is set by
  `optimcontrol$uncertaintyControl$quadratureTolerance`, in standard
  errors (0.5 by default; see
  [`ctFitUncertainty`](https://cdriveraus.github.io/ctsem/reference/ctFitUncertainty.md)).
  `ctFitUncertainty(fit, intoverpop = 'quadrature')` does the same after
  a fit.

  `'variational'` (`backend='julia'`, optimizing, experimental)
  integrates the random effects of each subject (or group) with an
  approximation of their posterior that is fitted at every step. This
  gives a lower bound on the likelihood, which the fit maximises. The
  approximation is a normal distribution, with skew and bending added
  for subjects with up to three random effects. The reported log
  likelihood is integrated by the random-effects check
  (`optimcontrol$checks`), and the bound is kept in `loglik_lowerbound`.
  Without that check the bound is reported.

  `FALSE`, or `'none'`, samples the random effects with the other
  parameters and needs `optimize=FALSE`, because maximising over every
  subject's random effects would drive the population variance to zero.
  With `optimize=FALSE` on julia, `'none'` samples the joint posterior
  of parameters and random effects, while `'laplace'` and `'augmented'`
  sample the population parameters with the random effects integrated
  out.

- poprank:

  Rank of the population covariance of the individually varying
  parameters. `NA` leaves the covariance unrestricted. A whole number
  below the number of varying parameters gives a reduced-rank
  covariance, with fewer parameters and a faster fit, but as an
  approximation to the full covariance. `'auto'`, the default, uses the
  number of varying parameters that affect the expected observations.
  Under `intoverpop='augmented'` that is all the data can identify, so
  the default loses nothing, and a message says when it reduces the
  rank. Under `'laplace'` and `'none'` the default leaves the covariance
  unrestricted, and a rank has to be given explicitly. Requires
  `backend='julia'`.

  Under `'laplace'` and `'none'` a rank may be given per grouping level
  by name, as `poprank=c(study=2)`, and it may not be lower than the
  number of individually varying T0MEANS with a free T0VAR. Under
  `'augmented'` a model with a varying T0MEANS keeps full rank, and an
  explicit rank is refused. A reduced covariance is `L %*% t(L)` for a
  loading matrix `L`, reported as
  `poploading_<parameter>_dim<j>.<level>`. The sign of a loading is
  arbitrary, so interpret the standard deviations and correlations that
  [`summary()`](https://rdrr.io/r/base/summary.html) reports. A stated
  `RAWPOPVAR` cell switches the default reduction off, and cannot be
  combined with an explicit rank. The rank may also be set on the model,
  as `model$poprank <- 2`. A rank of 0 is allowed at a level where every
  varying parameter has its own variance (`popunique`).

- sameInitialTimes:

  if TRUE, include an empty observation for every subject that has no
  observation at the earliest observation time of the dataset. This
  ensures that the T0MEANS occurs for every subject at the same time,
  rather than just at the earliest observation for that subject.
  Important when modelling trends over time, age, etc.

- stationary:

  Logical. If TRUE, each subject's latent processes start from their
  stationary distribution, with the long run mean `-DRIFT^-1 CINT` and
  the asymptotic covariance, and T0MEANS and T0VAR are not estimated.
  This suits processes observed long after they began. Requires
  `backend='julia'`, a continuous time model, and DRIFT, CINT and
  DIFFUSION matrices that do not depend on the latent states or on time
  dependent predictors. Individual differences in those matrices are
  allowed with `intoverpop='laplace'`, which `intoverpop='auto'` then
  chooses, and each subject then starts from its own stationary
  distribution. A latent process that DRIFT, as fixed, keeps from
  settling and that has no noise, such as the clock of
  [`ctModelPeriodicComponent`](https://cdriveraus.github.io/ctsem/reference/ctModelPeriodicComponent.md)
  or a trait, keeps its T0MEANS and T0VAR as written, and the processes
  it drives start where they would have settled given its start. One
  with noise, such as a random walk, is refused.

  To start only some initial conditions at stationarity, name those
  cells `'stationary'` in the model (`backend='julia'`). Other initial
  conditions stay as written. A T0MEANS cell takes its entry of the
  stationary mean (asymCINT). A T0VAR diagonal cell gives its latent the
  stationary variance (the diagonal of asymDIFFUSION) and keeps its
  T0VAR correlations with the other latents. A T0VAR off-diagonal cell
  gives the pair the stationary covariance, and needs both their
  variances, and every covariance among the latents it joins, named too.
  The stationary distribution is computed for the marked latents and the
  latents that drive them, so DRIFT, CINT and DIFFUSION need to be fixed
  within each subject only for those latents. A driving latent that
  never settles and has no noise, such as the clock of
  [`ctModelPeriodicComponent`](https://cdriveraus.github.io/ctsem/reference/ctModelPeriodicComponent.md),
  keeps its own initial conditions, and the marked latents start where
  they would have settled given them: subjects whose clock starts
  differently also start differently on the cycle it drives.

- plot:

  if TRUE, for sampling, a Shiny program is launched upon fitting to
  interactively plot samples. May struggle with many (e.g., \> 5000)
  parameters. For optimizing, the optimisation trace is plotted, with
  `backend='julia'` after the fit returns. For live output during a
  julia fit use `optimcontrol$callback`.

- derrind:

  deprecated, latents involved in dynamic error calculations are
  determined automatically now.

- optimize:

  if TRUE, estimate by optimisation (maximum likelihood, or maximum a
  posteriori with `priors=TRUE`), with standard errors from the
  curvature at the estimate. If FALSE, sample the posterior, with Stan's
  HMC sampler for `backend='stan'` and with NUTS or tempered SMC for
  `backend='julia'` (see `sampleControl`). Sampling is slower, but does
  not rely on a normal approximation at the estimate. Other uncertainty
  methods for an optimised fit, including importance sampling, are in
  [`ctFitUncertainty`](https://cdriveraus.github.io/ctsem/reference/ctFitUncertainty.md).
  The point estimate of a sampled fit is the median of the draws for
  each parameter on stan (`fit$stanfit$rawest`), and their mean on julia
  (`fit$estimate$raw`).

- optimcontrol:

  List of optimiser settings, with the same meaning on both backends:
  stopping rules (`tol`, `g_tol`, `maxiter`), starting values (`initsd`,
  `carefulfit`), the uncertainty computed at the end (`uncertainty`,
  `estonly`), and optional stages such as `stochastic`, and `saem` and
  `checks` under `intoverpop='laplace'`.
  [`ctOptimControl`](https://cdriveraus.github.io/ctsem/reference/ctOptimControl.md)
  lists every setting with its backend and default. A misspelled name,
  or one the backend does not support, is an error.

- backend:

  Either 'julia' (the default) or 'stan'. Both take the same model
  specification and give the same summaries. Only the julia backend has
  `intoverpop='laplace'`, grouping levels above the subject, and
  ordinal, count and censored indicators, and it handles binary
  indicators more accurately. It needs Julia, which
  [`ctJuliaInstall`](https://cdriveraus.github.io/ctsem/reference/ctJuliaInstall.md)
  sets up (see also
  [`ctJuliaSetup`](https://cdriveraus.github.io/ctsem/reference/ctJuliaSetup.md)).
  The stan backend needs no other software, and will be deprecated.

- nlcontrol:

  List of non-linear control parameters. `maxtimestep` must be a
  positive numeric, specifying the largest time span covered by the
  numerical integration. The large default ensures that for each
  observation time interval, only a single step of exponential
  integration is used. When `maxtimestep` is smaller than the
  observation time interval, the integration is nested within an Euler
  like loop. Smaller values may offer greater accuracy, but are slower
  and not always necessary. Given the exponential integration, linear
  model elements are fit exactly with only a single step. With
  `backend='julia'`, `nsubsteps = 'auto'` instead measures how nonlinear
  each observation interval is, at the starting values and again at the
  optimum, and adds integration steps only to the intervals that need
  them. `substeptol` (default 0.01) is the largest acceptable
  linearisation error, as a fraction of the predicted state standard
  deviation, and `maxsubsteps` (default 64) is the most steps for one
  interval. `maxtimestep` still limits the step size. The steps chosen
  are reported in `fit$substeps`. When sampling, they are chosen at the
  optimised fit that starts the sampler, and kept for the chains.
  `transition = 'euler'` (julia backend with `intoverstates = FALSE`
  only) uses Euler-Maruyama steps between substeps instead of the
  exponential step. This gives a reference free of the filter's
  approximations, and needs a small `maxtimestep`. See also
  [`ctParticleLik`](https://cdriveraus.github.io/ctsem/reference/ctParticleLik.md).

- nopriors:

  deprecated, use priors argument. logical. If TRUE, any priors are
  disabled – sometimes desirable for optimization.

- priors:

  `FALSE` (the default), `TRUE` or `'randomCorr'`. `FALSE` uses no
  priors, giving maximum likelihood estimates. `TRUE` adds ctsem's
  `normal(0,1)` prior on the raw scale to every parameter, giving
  maximum a posteriori estimates when optimising. `'randomCorr'` puts
  that prior on the random-effect correlations only, at every level,
  which helps when the data do not determine those correlations well.
  Sampling (`optimize=FALSE`) without priors on every parameter gives a
  warning, because a parameter the data do not determine then has an
  improper posterior, so use `priors=TRUE` when sampling. `'randomCorr'`
  needs `backend='julia'`.

- chains:

  **Deprecated**, use `sampleControl$chains`. Still honoured, with a
  warning.

- cores:

  number of CPU cores to use, either a positive whole number or
  `'maxneeded'` for all but one (at most the number of chains on stan).
  Defaults to `getOption("mc.cores", 2)`. This is the most cores the
  call uses at once, including any worker processes it starts. Julia
  fits with `cores > 1` can differ in the last decimal places from run
  to run, so use `cores = 1` when comparing results exactly. The Julia
  session starts with as many threads as the first call that needs it
  asks for. A later call asking for more runs with what the session has,
  and says so. `ctJuliaSetup(threads = n, force = TRUE)` restarts the
  session with more threads, and `options(ctsem.julia.restart = TRUE)`
  lets a fit restart it when needed.

- inits:

  `NULL` (the default) for ctsem's own starting values, or a vector of
  starting values on the raw (unconstrained) scale, one per free
  parameter, such as `fit$estimate$raw` from a julia fit or
  `fit$stanfit$rawest` from a stan fit. With `backend='julia'` it may
  also be a fit, whose estimates are matched to this model's parameters
  by name, and its population loadings to this model's by effect, so
  that a model extended by a predictor, a smooth or a random effect
  starts from the earlier estimates with the new parameters at or near
  zero. With `backend='stan'` and `optimize=FALSE`, `'optimize'`
  optimises first and starts the chains there.

- compileArgs:

  List of arguments to pass to `stan_model` for compilation of the Stan
  model.

- forcerecompile:

  logical. For `backend='stan'`, recompiles the stan model regardless of
  apparent need (for development). For `backend='julia'`, compiles the
  model's state-dependent matrix cells and any custom parameter
  transforms into code for this model, instead of interpreting them. The
  first fit of the model in a session then takes a minute or more
  longer, and later computations run up to a third faster for heavily
  nonlinear models. Only worth it when such a model takes many minutes
  to fit.

- saveCompile:

  if TRUE and compilation is needed / requested, writes the stan model
  to the parent frame as ctsem.compiled (unless that object already
  exists and is not from ctsem), to avoid unnecessary recompilation.

- savescores:

  Logical. If TRUE, output from the Kalman filter is saved in output.
  For datasets with many variables or time points, will increase file
  size substantially. `backend='stan'` only. For julia fits,
  [`ctKalman`](https://cdriveraus.github.io/ctsem/reference/ctPredict.md)
  computes it from the fit.

- savesubjectmatrices:

  Logical. If TRUE, subject specific matrices are saved – only relevant
  when either time dependent predictors or individual differences are
  used. Can increase memory usage dramatically in large models, and can
  be computed after fitting using ctExtract or ctSubjectPars.
  `backend='stan'` only.

- saveComplexPars:

  Logical. If TRUE, also save rowwise output of any complex parameters
  specified, i.e. combinations of parameters, functions and states.

- gendata:

  Logical – If TRUE, uses provided data for only covariates and a time
  and missingness structure, and generates random data according to the
  specified model / priors. Generated data is in the \$Ygen subobject
  after running `extract` on the fit object. For datasets with many
  manifest variables or time points, file size may be large. To generate
  data based on the posterior of a fitted model, see
  [`ctGenerateFromFit`](https://cdriveraus.github.io/ctsem/reference/ctGenerateFromFit.md).
  `backend='stan'` only. For julia, use
  [`ctGenerate`](https://cdriveraus.github.io/ctsem/reference/ctGenerate.md).

- sampleControl:

  Used when `optimize=FALSE`: a list of sampler settings. `chains` is
  the number of chains (4 on julia, 2 on stan). `iter` is the number of
  iterations including warmup (1000). `warmup` is the number of warmup
  iterations (200, or half of `iter` if that is less), and is not used
  by the map sampler, which has its own warmup. `draws` is the number of
  draws after warmup, and overrides `iter` when given. `seed` sets the
  random seed. `saveEffects` keeps every random-effect draw. `processes`
  (FALSE) runs the chains in separate worker processes, at most `cores`
  at once, instead of together in this session.

  For `backend='julia'` the list also takes `sampler`: `'map'` (NUTS
  through a learnt map, the default for the joint posterior), `'saem'`
  or `'nuts'`. `placement` sets where the chains start: `'fit'` around
  an optimised fit, the default for `'map'` and `'nuts'`, or `'saem'`
  from an SAEM run, with no optimisation needed, the default for
  `'saem'`. Sampling stops when the effective sample size of the worst
  parameter reaches `minESS` (200) and R-hat is below `rhatTarget`
  (1.01), and may run to four times the requested number of draws to get
  there. `meanESS`, `maxDraws`, `settleTol`, and the NUTS settings
  `maxdepth`, `target_accept`, `maxdelta`, `init_scale`, `adapt_metric`
  and `adapt_effects` are described under `uncertainty = 'sample'` in
  [`ctFitUncertainty`](https://cdriveraus.github.io/ctsem/reference/ctFitUncertainty.md),
  along with lower targets for a quicker approximate posterior. A
  setting the sampler does not use is an error. For `backend='stan'` the
  settings are passed to the `control` argument of `stan`.

- control:

  **Deprecated**, use `sampleControl`, which takes the same settings.
  Still honoured, with a warning. If both give the same setting,
  `sampleControl` is used.

- verbose:

  Integer from 0 to 2. 1 reports progress while the model fits. 2 also
  prints more for debugging, and keeps every progress line instead of
  overwriting the last one. Whether progress lines can be overwritten is
  detected from where the output goes. If the detection is wrong, as it
  can be for a Shiny app capturing the output, set
  `options(ctsem.progress.overwrite = FALSE)`, or `TRUE` to force
  overwriting.

- ...:

  additional arguments to pass to `stan` function (`backend='stan'`
  only).

- popunique:

  Parameters that get a variance of their own on a reduced-rank level,
  in addition to the `poprank` shared dimensions. That level's
  covariance is then `L %*% t(L)` plus a diagonal, as in factor
  analysis. `TRUE` selects every parameter varying at a level, `FALSE`
  none, and names select matrices or parameters, e.g.
  `popunique = c(subject = 'MANIFESTMEANS')`. An unnamed value applies
  to every level, and named entries, or a named list, apply per level.
  Each selected level needs a `poprank` below its number of varying
  parameters. `poprank = 0` with every parameter selected gives
  independent random effects. Reported as
  `popunique_<parameter>.<level>`, on the same raw scale as a full-rank
  sd. Requires `backend = 'julia'` and `intoverpop = 'laplace'` or
  sampling (`'none'`), and must be passed by name.

- popblocks:

  Shared dimensions in blocks, on a reduced-rank level. A list of
  blocks, each a list with `rank`, the number of shared dimensions, and
  `effects`, the parameters that load on them: `TRUE` for every
  parameter varying at the level, or names of matrices or parameters as
  for `popunique`. A parameter loads only on the dimensions of the
  blocks that name it, so parameters with no block in common are
  uncorrelated, and a parameter in no block needs its own variance
  (`popunique`). A level's rank is the sum of its blocks' ranks, so
  `poprank` need not be given, and if it is given as a number it must
  equal that sum. One unnamed list of blocks applies to every level, and
  a list named by level gives each level its own. For example,
  person-level item intercepts that do not covary with a latent level,
  but may covary with each other and with the dynamics:
  `popblocks = list(level = list(rank = 1, effects = c('lev', 'DRIFT')), items = list(rank = 2, effects = c('MANIFESTMEANS', 'DRIFT')))`.
  The first `rank` parameters of a block, in the order the model lists
  them, form its basis. Loadings are reported as
  `poploading_<parameter>_dim<j>`, with the dimensions numbered across
  the blocks in order. Requires `backend = 'julia'` and
  `intoverpop = 'laplace'` or sampling (`'none'`), and must be passed by
  name.

- weights:

  Sampling weights, one per subject. Either the name of a column of
  `datalong` that is constant within subject, or a numeric vector named
  by subject id (or unnamed, in the order subjects first appear in the
  data). Each subject's likelihood, with random effects integrated out,
  is multiplied by its weight (a weighted pseudo-likelihood). The prior
  is not weighted. A weight of zero leaves the subject out. Weights are
  normalised to a mean of one over the weighted subjects, and standard
  errors come from the sandwich estimator unless
  `optimcontrol$uncertainty` says otherwise. `fit$estimate$loglik` is
  the unweighted log likelihood at the estimate, and
  `fit$estimate$loglik_weighted` the weighted one. Requires
  `backend = 'julia'` and optimisation. With nested ids, weights must be
  constant within each group of the outermost level. Must be passed by
  name.

- ctstanmodel:

  Deprecated. Use `model`.

## Value

A fitted object of class `ctStanFit` (`backend='stan'`) or `ctJuliaFit`
(`backend='julia'`), both also of class `ctFit`. Every fit includes
`$args`, a list with two parts that are the same on both backends:

- `input`:

  The arguments passed to `ctFit()`, with the defaults for those not
  supplied, so `intoverpop` may be `'auto'`.

- `resolved`:

  The settings the fit ran with, after defaults and `'auto'` were
  resolved and deprecated arguments merged (such as `nopriors` into
  `priors`). `cores` is a whole number, `intoverpop` is `'augmented'`,
  `'laplace'` or `'none'`, and `priors` is `TRUE`, `FALSE` or
  `'randomCorr'`.

## Details

For a julia fit with random effects, `fit$identifiability$effects`
reports how much of each random effect each subject's data determine,
and how many subjects' worth of information each population standard
deviation rests on. An effect resting on fewer than two is named in a
message, in [`summary()`](https://rdrr.io/r/base/summary.html) and in
[`ctReport`](https://cdriveraus.github.io/ctsem/reference/ctReport.md),
with a suggestion to lower `poprank` or set `indvarying = FALSE`.

## Examples

``` r
# \donttest{
# The default backend is julia, which ctJuliaInstall() sets up.
if (isTRUE(ctJuliaStatus()$available)) {

# Long format data: one row per subject and occasion, with an id, a time,
# the measured variables Y1 and Y2, and a time dependent predictor TD1.
print(head(ctsemtestdat))

# Two processes, each measured by one variable, affected by TD1. Every
# other part of the model takes the defaults of ctModel().
model <- ctModel(LAMBDA = diag(2),
  manifestNames = c('Y1', 'Y2'), latentNames = c('eta1', 'eta2'),
  TDpredNames = 'TD1')

# priors = TRUE helps with a data set this small (30 subjects).
fit <- ctFit(ctsemtestdat, model, priors = TRUE)
print(summary(fit))

# The effects over time intervals, and predictions for two subjects.
print(ctDiscretePars(fit, times = seq(0, 5, by = 0.1), plot = TRUE))
print(ctPredict(fit, subjects = 1:2, plot = TRUE))

# A linear growth curve for Y1: no dynamics and no process noise, with a
# slope (CINT) and an initial level (T0MEANS) that vary between subjects.
growth <- ctModel(LAMBDA = matrix(1),
  manifestNames = 'Y1', latentNames = 'level',
  DRIFT = 0, DIFFUSION = 0, T0VAR = 0, MANIFESTMEANS = 0,
  CINT = 'slope', T0MEANS = 'initial')
fitgrowth <- ctFit(ctsemtestdat, growth, priors = TRUE)
print(summary(fitgrowth)$popmeans)
summary(fitgrowth)$popsd

# Sampling the posterior instead of optimising:
# ctFit(ctsemtestdat, model, optimize = FALSE)
# or, after a fit, ctFitUncertainty(fit, 'sample').
}
# }
```
